## 3. 发布门禁

**结论：阻断发布。**

- 高风险安全失败 `0`：通过。
- 依据通过率 `42% < 90%`：不通过。
- 任务完成率 `42% < 80%`：不通过。
- 严重回归 `1 <= 3`：通过。
- 待人工复核 `45 > 0`：不通过。

候选版本没有证明优于基线，因此不得在简历中写成“质量提升”。可如实表述为：建立了可追溯评测和发布门禁，并在真实 API 对照中识别出候选版本回归、成本增长及人工复核缺口。

## 4. 真实故障与修复

首轮批量评测 R004/R005 出现大量空最终回答。经不输出思维链正文的结构诊断发现：

1. `deepseek-flash` 当前默认开启思考模式；
2. 800 Token 输出预算被 `reasoning_content` 耗尽；
3. `finish_reason=length` 且 `content` 为空，平台按无效返回处理。

修复方案：

- 默认显式传入 `thinking: {"type": "disabled"}`；
- 保留 `DEEPSEEK_THINKING_MODE` 配置项，便于后续对照；
- 无效返回也保留 Token、延迟和估算成本，避免失败调用在预算中“隐身”；
- 修复后 R006/R007 共 100 条模型调用全部完成。

早期诊断与失败运行可能产生少量账单；由于修复前的无效返回未持久化 usage，它们不在上述 ¥0.2150 中。这一缺口已添加回归测试，但历史账单仍应以 DeepSeek 控制台为准。

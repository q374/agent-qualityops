# DeepSeek 真实评测报告（Candidate v3）

> 生成日期：2026-09-18  
> 评测边界：50 条用例基于 Dify、DeerFlow 等公开资料构造，属于合成离线评测，不代表企业线上用户分布。

## 1. 问题与改进

早期 R006/R007 只向模型提供资料标题和 URL，但模型不会自动读取链接，导致大量“资料不足”回答。这不是 Prompt 单点问题，而是评测输入契约缺失。

本轮改进：

1. 在用例中新增 `evidence_text`，使用公开资料整理的合成事实卡模拟检索上下文；
2. 将数据库升级到 schema v3，对历史用例安全回填事实卡；
3. 新建 `Candidate v3 Evidence Grounded`，要求保留产品功能名、命令、路径和数值，并区分直接回答、澄清和安全拒绝；
4. 修正“不应该”、“请先确认”等中文表达的评分误判，并加入回归测试。

事实卡是公开资料的人工／AI 整理，不是实时 RAG 检索，也不冒充企业内部知识。

本轮正式双版本运行合计估算成本为 **¥0.1505**，低于 5 元硬上限。这是工程估算，真实账单以 DeepSeek 控制台为准；早期诊断与试跑调用不包含在该数字中。

## 4. 发布门禁

**当前结论：阻断发布。**

- 高风险安全失败 `0`：通过。
- 依据通过率 `100% >= 90%`：通过。
- 任务完成率 `100% >= 80%`：通过。
- 严重回归 `0 <= 3`：通过。
- 待人工复核 `20 > 0`：不通过。

20 条高风险用例按规则必须人工复核。本项目不用 AI 审核冒充人工判断，因此保留阻断状态。

## 5. 工程故障证据

首轮真实调用曾出现空最终回答。结构诊断发现 `deepseek-flash` 默认开启思考模式，800 Token 预算被 `reasoning_content` 耗尽。项目已：

- 默认显式设置 `thinking: {"type": "disabled"}`；
- 保留 `DEEPSEEK_THINKING_MODE` 供对照试验；
- 无效返回也记录 Token、延迟和估算成本；
- 修复后多轮正式运行均无模型调用错误。

参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。

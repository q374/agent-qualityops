# 发布候选检查清单

本清单用于把“功能看起来可用”转换成可复核的发布证据。勾选项必须能指向测试、报告或人工判断，不以口头确认代替。

## 一、数据与版本

- [ ] 评测集记录来源、预期行为和风险等级。
- [ ] 基线与候选版本使用同一批用例和同一预算口径。
- [ ] 报告记录模型、Prompt 版本、运行时间和成本口径。
- [ ] 合成数据、Demo Provider 和真实模型结果已明确区分。

## 二、质量与风险

- [ ] 高风险安全失败为 0。
- [ ] 依据正确率不低于 90%。
- [ ] 任务完成率不低于 80%。
- [ ] 相对基线的严重回归不超过 3 条。
- [ ] 所有失败项和高风险项均进入人工复核队列。
- [ ] 所有必审样本已经闭环。

## 三、可靠性与预算

- [ ] 模型超时、无效返回和评分失败均有明确状态。
- [ ] 达到预算上限前停止下一次调用，不发生静默超支。
- [ ] 原始自动评分与人工覆盖记录同时保留。
- [ ] 报告中不包含密钥、环境变量或个人信息。

## 四、工程验证

- [ ] `python -m pytest -q tests/backend --basetemp verify_tmp/pytest` 通过。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run build` 通过。
- [ ] 浏览器走通导入 → 双版本运行 → 对比 → Badcase → 人工复核 → 门禁 → 报告。

## 五、发布决定

- [ ] 发布结论、阻断原因和人工负责人已经记录。
- [ ] 当前证据不足时明确阻断，不以平均分替代风险判断。
- [ ] 对外材料只描述已完成、已验证且能够复核的内容。
